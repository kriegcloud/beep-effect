# Brief — research-stage draft

## Problem

Beep needs evidence that navigation tools improve complete standards-compliant implementations and reuse, rather than merely returning plausible symbols. Existing retrieval studies and estimated savings do not answer this repository-specific question.

## Appetite

Three real tasks and three named coding models, with twelve eligible graph configurations and no graph: up to 117 candidate coding cells before supported-interface decisions. Full launch appetite is conditional on measured pilot resource estimates, subscriptions and machine capacity. Only $30 existing Jev credit is authorized; no new billing or overage. This local experiment expires 2026-11-09 or at completion earlier.

## Solution Sketch

Compose the existing metrics, evals, process, worktree and Yeet seams into a narrow disposable receipt-emitting runner. First prove one control and one graph cell end to end; then freeze task acceptance/common base/protocol and full index snapshots. Compare within task and coding model. Preserve failures and all local commits. Deterministic gates precede fresh blinded model review and operator grading of the top three passing finalists per task plus close calls.

## Rabbit Holes

Multi-surface treatment integration; cached-input accounting; unsupported native telemetry; expensive semantic ingestion; same-root IDE indexing; inherited baseline reds; sealed reuse oracles; exact-final proof binding; the distinction between graph absence and source absence. Each remains an explicit gate rather than a waiver.

## No-Gos

No production index/wiring changes, memory-service restoration, trial publishing, hidden oracle leakage, paid endpoint substitution, reduced ingestion depth, undocumented wrapper advantages, pooled model ranking, opaque confidence score, or claims of significance from one run per cell. Do not weaken goal specs or full Yeet to fit a benchmark.
