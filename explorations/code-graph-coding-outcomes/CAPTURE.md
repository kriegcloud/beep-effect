Validate each tool's output/path parser with one known-correct and one known-wrong case, retaining raw responses. A tool that is never invoked is an adoption result, not proof its graph is bad. Do not give Graft-only federated Effect graph access unless every tool/control has an equivalent reference corpus; evaluate external-reference indexing separately if it matters after this result.

Run distinct worktree roots sequentially or with provably isolated IDE projects, and account for IDE indexing, warm caches, file-sync behavior, and plugin availability. Prevent WebStorm from serving symbols from another arm or a different Beep checkout. Record whether dependency-index search, refactoring, or debugging was actually used. Add a separate, source-checked capability probe for the JetBrains-only tools so their availability is visible even when a coding agent never chooses them; do not force those calls in scored coding runs. If the IDE backend cannot be made reliable for a model/harness, mark that cell unsupported with evidence; do not silently substitute the LSP backend. Capture **observed** input, output, cache-read/cache-write tokens where available; request/turn counts; tool calls/adoption; elapsed time; interventions/retries; task-specific check outcomes; full Yeet receipt; defects; final local commit; and comparable estimated cost. Use `null` for unavailable counts, never zero. Separate index preparation from session cost and show total ownership under declared amortization horizons. Preserve disagreements; do not collapse grades into one opaque confidence number or let them override deterministic failures.

Select on pass rate and quality/reuse first, then observed time/tokens and setup/upkeep. Report each dimension and distributions, including failed and unknown cells. Compare tools with no graph **within model and task** and state the limits of a single run per cell. Provide a sensitivity view with historical Graft prep included and excluded. Do not claim statistical significance from this small matrix.
