# Reflection. repository-simplification-confidence (2026-10-16, codex)

## Summary

The program landed retirement, script, release-policy, CI, completion-evidence,
telemetry and configuration safety changes across eighteen implementation and
repair PRs. Its operational mission remains partly unmet. Closeout retains
that evidence and transfers explicit work to issues under the assigned brief;
completed-retained describes this accounting disposition, not honest-zero debt.

## Tooling experience

- **Worked:** dated handoffs, supported owner commands and source-bound receipts made partial deliveries auditable. Graft located goal/reflection validation without broad source reads.
- **Didn't:** treating lane PR merges as program acceptance would have hidden the remaining A/B/H1/V work and unknown Desktop routes.
- **Frustrating:** README and PLAN status still described early phases while F was merged. Missing promised receipts were visible only during the acceptance join.
- **Wished existed:** a handoff validator requiring acceptance IDs, exact evidence revisions, residual owner/gates and distinct candidate/final signals.

## Implementation improvement opportunities

Keep the one parsed TOML/JSON eligibility gate and typed refusal boundary.
Do not re-enable format writing by adding another lexical case. The three
publication protocol improvements and native qualification prerequisites have
explicit successors in the stage-6 audit. Preserve backup and crash artifacts
while those protocols evolve.

## Goal & prompt critique

The launcher should state the exact write boundary and publication signal,
and every lane should report which acceptance IDs its current PR closes.
The original broad promise of zero actionable debt needs a measured per-cohort
budget; refreshing an inventory does not execute that remediation. A closeout
brief that permits successors should explicitly distinguish an accounting
closure from completion of the original operational outcomes, as this PR does.

The private driver lessons were used as supplied operational testimony,
corroborated where possible by the public F/H3 handoffs and panel verdicts.
Private machine/session identifiers and raw launcher credential setup are
omitted. App shutdown killed lane units, the direct Fable seat hit its weekly
limit, and one unquoted heredoc damaged a prompt: use durable files, safely
quoted writes and explicit launch identity evidence. The same-model proxy
route preserved panel membership; a quota failure was never a passing verdict.

## Lessons (confidence-tiered)

- **HIGH. Critical:** a merge final is an operational trigger. Emit it only at the authorized gate; use a candidate marker during panel work.
- **HIGH. Critical:** retain unknown outcomes. Zero applies, unknown native windows and untested Desktop routes cannot become reclaimed bytes, non-use or permission safety.
- **HIGH. Critical:** test portability and dependency installation before attributing a red to main. Preserve failed attempts and correct attribution explicitly.
- **MEDIUM. Best practice:** precommit a review round cap and structural scope cut. The F panel found continuing parser edge cases until the certification surface narrowed.
- **MEDIUM. Best practice:** join acceptance items to source-bound receipts before flipping state. Retain unfinished work as owned successors without claiming the original outcome.
- **LOW. Consideration:** a generated acceptance-to-handoff join could reduce future closeout cost, provided it never infers semantic acceptance from a PR title or merge alone.
