# Reflection — epistemics-foundation-extraction (2026-10-22, claude)

## Summary

The tenant-free epistemic vocabulary now lives in the foundation/modeling package `@beep/epistemics`.
Four modules moved unchanged. Seven id-bearing modules became generic builders and behavior factories
that the slice binds to its shared-domain ids. New in the package: `ValidInterval`, `KnowledgeInterval`
and the `Claim<P>` envelope. #2017 merged as `ab6000add2`, and it left three hosted-only reds on main.
I fixed all three that day: Docgen and Lint Policy in #2019 (`9439053a3f`), JSDoc Ratchet in #2021
(`07f8856fec`). Verdict: the design held up, and the gaps in my pre-publish checks were expensive.

## Tooling experience

- **Worked:**
  - `beep create-package` got the new package right the first time, including the identity
    registration.
  - Subagent lanes with a written contract: an Opus child moved the modules and built the P1b
    factories, and it surfaced both blockers (shared-kernel ids, TS2509) instead of working around
    them.
  - `yeet reply` drafts closed 18 review threads cleanly across rounds.
  - The cache-baseline recipe in the yeet references produced a reviewed request the orchestrator
    accepted as S31b registration.
- **Didn't:**
  - Cheap-gates was green, yet three required checks failed after merge.
  - `worktree new` branched every lane from the primary clone's HEAD.
  - `yeet publish --push-only` couldn't push a merge-only commit without a full local proof.
  - One `yeet sweep --retire` judged a lane by main's tip, printed "branch main: deleted" (main was
    fine), and left the lane branch behind.
- **Frustrating:**
  - Messages crossed in flight. Idle notices from the subagent repeated stale states several times,
    so each one had to be checked against the newest instruction.
  - The 1Password desktop app exited mid-session, which blocked signed commits until it was relaunched
    and unlocked.
- **Wished existed:** one command that runs every hosted Repo Sanity, Lint Policy, Docgen and JSDoc
  Ratchet body locally for the changed packages, with the inventory regenerated to scratch.

## Implementation improvement opportunities

- Three `as` casts came over verbatim from the slice (`CanonicalJson.ts`, `Contradiction.model.ts`
  `objectEntries`/`childValues`). Replace them with schema-checked narrowing in a follow-up.
- The order check for `ValidTime.Interval` sits on the union. A per-case check would give clearer
  decode errors if `S.TaggedUnion` grows per-member refinement.
- `EpistemicFixtureKey` stays slice-local by decision. If party needs fixture keys too, it should move
  to foundation as an id-free value.

## Goal & prompt critique

- The SPEC inventory should have had a column "imports outside the slice" next to "tenant-free". The
  P0 census counted importers of each module, not what each module imports. Proposed edit to the
  inventory table header: `| Module | Moves | Imports outside this slice | Notes |`.
- The non-goal "persistence shapes byte-identical" held. Add "schema identifiers byte-identical" to the
  Constraints section: it was the property that made the factory design safe to merge, and the
  identifier-diff test should be required.
- The P3 exit criterion said `mergeStateStatus` is `CLEAN`, but repo merges run through the
  orchestrator's relaxed S43 gate. Point the criterion at "merged by the orchestrator gate".

## Lessons (confidence-tiered)

- **HIGH — Critical:** For a new package or a schema move, run `beep lint schema-catalog --write`, root
  `bun run lint:oxlint`, `beep docgen check --package <pkg>` and the JSDoc ratchet against a
  regenerated inventory before publishing. All four are hosted-only today, and each one cost a
  same-day unblocker.
- **HIGH — Critical:** When a design hits a type-system wall (TS2509), stop and pick a shape with the
  operator. Don't widen types. Structural types would have silently changed `.make` and instance
  semantics across 25 classes.
- **MEDIUM — Best practice:** Prove a refactor in the shape a reviewer can check: an identifier-listing
  diff (258 identifiers, 0 changed), a type-level equality test with a negative probe, and a
  row-compatibility round-trip.
- **MEDIUM — Best practice:** Before implementing a gate change an orchestrator specifies, confirm the
  trigger. The fallow "introduced-only" change would have deleted the dead-code gate. The real trigger
  was the 3.34 glob semantics, and #1934's pin had already fixed it.
- **LOW — Consideration:** Batch subagent instructions in one message. Sequential messages to an idle
  agent produced replies that crossed and had to be reconciled.
