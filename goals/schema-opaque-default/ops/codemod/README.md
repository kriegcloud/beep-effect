# schema-opaque-default codemod

A committed, re-runnable AST codemod for the `schema-opaque-default` goal. It
makes branded `S.Opaque` the default shape for plain-data schema classes and
brands every remaining schema class. The contract is the packet
[`SPEC.md`](../../SPEC.md) Decision Log (D1-D8).

| File | Role |
| --- | --- |
| `run.ts` | Phase A, the codemod: discovery, IO, Biome formatting, report. |
| `codemod.ts` | Pure core: AST index, keep-class analysis, the transforms. |
| `fixup.ts` | Phase B, diagnostics-driven consumer fix-up after branding. |
| `codemod.test.ts` | Fixture tests for the core (`bun test goals/schema-opaque-default/ops/codemod`). |
| `keep-class.jsonc` | Durable keep-as-class exceptions honoured on every re-run. |

## Usage

Run every command from the repository root.

```sh
# Phase A: rewrite the declarations (idempotent).
bun run goals/schema-opaque-default/ops/codemod/run.ts [--paths <glob>...] [--report out.json]

# Prove idempotence: exits 1 when any file would still change.
bun run goals/schema-opaque-default/ops/codemod/run.ts --check

# Reverse D1 (forward-shaped S.Opaque back to S.Class / S.TaggedClass).
bun run goals/schema-opaque-default/ops/codemod/run.ts --reverse [--paths <glob>...]

# Phase B: feed compiler output to the fix-up, then re-check.
bun run beep check > check.log 2>&1
bun run goals/schema-opaque-default/ops/codemod/fixup.ts check.log [more.log...] [--check] [--report out.json]
```

`--paths` limits which files are rewritten; the cross-file index always spans
the whole scope, so keep-class decisions do not depend on the glob.

Diagnostic positions in a log are only valid for the tree that produced it.
Re-run the check before re-running `fixup.ts`, or narrow it to files that have
not changed since with `--only <file>...`.

## Scope

Tracked and untracked-but-not-ignored `*.ts` / `*.tsx` under `apps/`,
`packages/`, `infra/`, `scratchpad/`, `goals/`, `explorations/` and `tools/`.
Excluded: `node_modules`, `dist`, `.repos`, `.d.ts`, and files whose leading
comment marks them generated (`@generated`, `auto-generated`, `generated by`,
`do not edit`, ...), and sample projects nested under a `fixtures/` directory
(an ancestor below `fixtures/` has its own `tsconfig.json` or `package.json`):
their exact source is a test expectation. Generated files are fixed in their
generators, not here.

The Schema namespace is resolved per file by binding: `import * as S from
"effect/Schema"` (any alias, including relative `.../Schema.ts`), `import {
Schema } from "effect"`, `import * as Effect from "effect"` (`Effect.Schema`),
and the conventional `S` / `Schema` / `SchemaModule` names in files that
dynamically `import("effect/Schema")`.

## Transforms

Only class declarations and class expressions whose `extends` clause is one
of the five schema constructors are touched.

1. A declaration that already has a second (brand) type argument is left
   unchanged, whatever its shape.
2. `S.Error`, `S.TaggedError` and `S.Opaque` get the brand:
   `S.TaggedError<X, { readonly brand: unique symbol }>(...)`.
3. `S.Class<X>(ID)(FIELDS[, ANNOT])` and `S.TaggedClass<X>(ID?)(TAG, FIELDS[, ANNOT])`
   either stay a branded class (keep reasons below) or convert (D1/D3) to
   `class X extends S.Opaque<X, { readonly brand: unique symbol }>()(SOURCE) { BODY }`
   with the body (statics) kept verbatim:
   - `SOURCE` is `S.Struct(FIELDS)`, `S.TaggedStruct(TAG, FIELDS)` for a
     TaggedClass, or `FIELDS` itself when it already is a Struct
     (`S.Struct(...)`, `.mapFields(...)`, `.check(...)` / `.annotate(...)`
     chains, resolved through local consts and relative imports).
   - A plain Class whose literal fields carry `_tag: S.tag("t")` or
     `_tag: S.Literal("t")` becomes `S.TaggedStruct("t", rest)` (the
     `schemaStructWithTag` rule rejects a Struct with a `_tag` field). Any other
     `_tag` field keeps the class (`tag-field`).
   - The annotation keeps the identifier the class carried:
     - `$I.annote(name, extras)` / `$I.annoteClass(...)` →
       `.pipe($I.annoteSchema(name, extras))` (same identifier, title,
       schemaId and extras: `annoteSchema` is `annote` applied to the schema);
     - no annotation and an identity-tag ID `` $I`Name` `` →
       `.pipe($I.annoteSchema("Name"))`;
     - no annotation and any other ID: `.pipe($I.annoteSchema("ClassName"))` when
       the module has an identity composer (`const $X = <pkg>.create(...)` or an
       imported `$I`; the identifier becomes `$I/ClassName`, the spelling the
       schema-first lint requires), otherwise `.annotate({ identifier: ID })`
       (`TAG` for a TaggedClass without an ID, matching `TaggedClass`'s
       default);
     - an object-literal annotation: `.pipe($I.annoteSchema("ClassName", { ...props }))`
       with a composer, otherwise `.annotate({ identifier: ID, ...props })`,
       unless it already sets `identifier`;
     - any other annotation expression → `.annotate({ identifier: ID }).annotate(ANNOT)`,
       which keeps the class precedence (the annotation overrides the ID).
   - Comments in the rewritten spans move next to the emitted code.
   - Re-runs also normalize an existing forward-shaped
     `S.Opaque<X, B>()(SOURCE.annotate({ identifier, ...rest }))` to
     `.pipe($I.annoteSchema("X", { ...rest }))` when the module has a composer.
4. A schema whose fields declare a `brand` key gets
   `{ readonly nominal: unique symbol }` instead: intersecting a `brand: string`
   field with `{ readonly brand: unique symbol }` reduces the type to `never`.
5. JSDoc examples cannot `new` an `S.Opaque` (its constructor takes `never`):
   inside `/** ... */` comments, `new X(` becomes `X.make(` for every `X` that
   ends up as `S.Opaque` in the comment's package.
6. The codemod never chooses a `{}` brand, a cast or an `@effect-diagnostics`
   directive on its own; brand overrides come only from `keep-class.jsonc`.

`TaggedStruct(tag, fields)` builds `_tag` with `S.tag(tag)` (a constructor
default), so `X.make` keeps `_tag` optional exactly as `TaggedClass.make` did.

### Keep reasons

A plain-data `S.Class` / `S.TaggedClass` stays a class (branded) when any of
these hold:

| Reason | Trigger |
| --- | --- |
| `effected-port` | File under `scratchpad/effected/`, or an upstream test copied beside it: `scratchpad/test/<module>/**` or `scratchpad/test/<module>.test.ts` for a module with a `scratchpad/effected/<module>/` source directory (D6). |
| `instance-member` | Non-static property, method, accessor, constructor or index signature (`declare` fields count). |
| `static-super` | A static member reads `super` (`static override make(...) { return super.make(...) }`). Schema `make`/`makeEffect`/`makeOption` are memoized by prototype getters that `defineProperty` onto `this`, so on an `S.Opaque` the first `super.make` replaces the override. An existing `S.Opaque` with such a member is reversed to a branded class. |
| `extend-root` | `X.extend(...)` anywhere (Opaque has no `.extend`, D2). |
| `subclassed` | `class Y extends X` directly. |
| `instanceof` | `v instanceof X` or `S.instanceOf(X)`. |
| `new-site` | `new X(...)` anywhere (sites are reported). |
| `keep-class-allowlist` | Listed in `keep-class.jsonc`. |
| `fields-expression-unknown` | The fields argument is neither a record nor a provable Struct. |
| `tagged-struct-source` | A TaggedClass given a Struct (its `mapFields` merge has no Opaque spelling). |
| `declaration-hooks` | The annotation sets `to*` hooks typed for a Declaration. |
| `tag-field` | A plain Class with a non-literal `_tag` field. |
| `unrecognized-shape` | Anything else the transform does not model. |

References resolve across files through a repo-wide name index: local
declarations first, then the import specifier (relative paths and barrels,
workspace packages restricted to their own directory). External modules and
`globalThis` never match. An unresolvable workspace reference keeps every
candidate class (conservative).

### `keep-class.jsonc`

Keep-as-class entries are `{ "file": "<repo-relative path>", "class": "<Name>", "reason": "<why>" }`.
On every run an allowlisted class stays a branded class; an allowlisted class
that is already a forward-shaped `S.Opaque` is reverted to `S.Class` /
`S.TaggedClass`.

Brand-override entries add `"brand"`, are documented schema-first exceptions to
D4, and never force class semantics:

- `"brand": "structural"` gives the class the `{}` brand. Used for recursive
  ASTs whose children are typed by hand-written namespace `Type`s (needed by
  `S.suspend` to break the class/base-type cycle) that must stay structurally
  equal to the classes; `"class": "*"` selects every class of the file that has
  a same-named `declare namespace X { Type ... }`.
- `"brand": "alternate"` gives the class `{ readonly nominal: unique symbol }`,
  for schemas whose type is intersected with another branded schema (two
  `brand: unique symbol` keys reduce the intersection to `never`, e.g. xstate
  state contexts merged with the machine context).

The file header records the measured evidence for each override. Add an entry, with its reason, whenever a schema genuinely
needs class semantics (constructor type, `.identifier`, `instanceof`, an
`S.Class`-typed generic constraint) instead of hand-editing codemod output.

## Fix-up (phase B)

Branding makes plain objects no longer assignable to schema class types.
`fixup.ts` reads `tsgo` output and applies only the fixes the diagnostic
proves:

- brand mismatch on a bare schema type `X` → `X.make(<value>)`, following
  `Types of property 'p'` hops into object literals, array elements (matched by
  `_tag` when `X` is tagged), arrow-function bodies and `return` values. A
  type-only import of `X` becomes a value import; a missing one is added
  (relative path inside the package, the `./*` export subpath across
  packages). A private class that already shapes another module's calls is
  exported, with a JSDoc built from its annotation description;
- `TS2554` on `X.make()` → `X.make({})` (an all-optional Struct takes its
  input object explicitly, unlike `Class.make`);
- `TS2527` on `export const A = B` → `export const A: typeof B = B`; any other
  `TS2527` (an inferred type inlines a branded class its module does not export)
  exports the hidden classes the site's modules reach through exported
  declarations.

Safety rules: only names that are schema classes are wrapped; a name bound to an
external module (`import * as P from "effect/Predicate"`) is never treated as the
class; a class picked out of a union target is wrapped only for a literal whose
`_tag` names it; a class with a discriminant `S.tag` field (`mode`, `level`, ...)
is wrapped only for a literal that writes that discriminant as the class's own
literal (otherwise use the union schema's `.make`); a value that already is a
`.make(...)` argument is never wrapped again; package tests import through the
package's public `@beep/*` path. Everything else is listed in its report as
manual work.

## Re-running after merges (D7)

Conflicts are resolved by re-running, never by hand-merging codemod output:

1. Take `origin/main` versions of the conflicting files.
2. `run.ts --paths <files>`; then `run.ts --check` must exit 0.
3. Re-run the check and `fixup.ts` on the fresh log; repeat until the fix-up
   reports nothing it can fix.
4. Re-apply the remaining manual consumer edits.
