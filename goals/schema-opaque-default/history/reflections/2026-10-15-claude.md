# Reflection — schema-opaque-default (2026-10-15, claude)

## Summary

The goal landed. Plain data schemas are branded `S.Opaque` over `S.Struct`/`S.TaggedStruct` by default, every schema class carries a nominal brand (168 documented structural exceptions, D9), and `schemaClassMissingBrand` is now `"error"` in the Effect diagnostics lane. The work shipped as #1758 (codemod + output, about 5,800 declarations), #1776 (the 0.52 `preferEffectArray` sites and the labs fallout), two main unblockers caused by #1758 (#1783 episode 16; the skills-provenance fix folded into #1773) and the episode-19 sweep #1798, and this closing PR, which arms the rule and adds `lint:opaque-roundtrips`.

## Tooling experience

- **Worked:** a committed, re-runnable AST codemod with `--check`, plus `fixup.ts` driven by compiler logs, made every main merge mechanical: take main's side, re-run, fix up. Detached `systemd-run` proof chains survived session restarts and OOM kills. A type-checker scan with a positive control (the pre-fix test must still flag 4) separated real risk from the 149 harmless Opaque `toStrictEqual` asserts.
- **Didn't:** `bun run check` skips labs, and the unit sweep skips integration suites, so two classes of #1758 fallout reached main. tsc-rs compiled one rule set in, so the 0.52 proof needed a temporary install and a disarm script.
- **Frustrating:** main moved roughly ten commits an hour during the merge window, and each catch-up cost about 40 minutes, until the orchestrator froze main for the final merge. Line-keyed inventories had to be re-carried by hand every round.
- **Wished existed:** an inventory writer that preserves exception reasons across moved lines, and a single "everything the codemod could have broken" proof command covering labs and integration suites.

## Implementation improvement opportunities

- Fold the three repeated manual fix shapes into `fixup.ts` (see the codification finding).
- Move plain-`S.Class` persisted entities onto the effect-drizzle kit (D5 follow-up).

## Lessons (confidence-tiered)

- **HIGH — Critical:** After a repo-wide rewrite, prove every surface the rewrite touched, including filtered workspaces and non-unit suites. Two main reds came from surfaces the standard proof skips.
- **HIGH — Critical:** When `make` starts validating, audit test data that was deliberately invalid. Build those inputs with `{ disableChecks: true }` so negative tests still reach the code under test.
- **MEDIUM — Best practice:** Prefer one consolidated unblocker per red episode, with the owner of the cause diagnosing it. The skills-provenance and Postgres reds were each fixed once, in the episode's single PR.
- **LOW — Consideration:** A merge freeze is cheaper than racing a fast-moving main with a PR that touches thousands of files.
