# Reflection — effect-string-migration (2026-10-22, claude)

## Summary

The goal moved every native `String.prototype` call the `preferEffectString` rule flags to `effect/String`. That was 2,992 sites by deduplicated `file(line,col)`, across 16 wave PRs plus the #2009 fix. Wave 7 then moved the reviewed `@effect/tsgo` pin to 0.55.0 and armed the rule at `error`. Verdict: achieved, with no exceptions, baselines or directive entries added. The scope roughly doubled mid-goal when the effected promotions landed, and the wave plan absorbed it.

## Tooling experience

- **Worked:**
  - The temporary 0.55.0 install plus `bun run beep quality effect-diagnostics --filter`. It proved each wave at zero own-file findings without moving the pin.
  - Lane-vs-main per-file lcov comparison: swap main's sources in, same tests. It caught every unreachable fallback branch before hosted CI.
  - Codex lanes (`gpt-6.1-sol` medium), run in parallel with a shared prompt template that accumulated each wave's review lessons.
  - `yeet reply` for thread answers.
  - `ev-rekey.py`, which re-keys moved effect-vitest rows in place instead of rewriting the inventory with `--write`.
- **Didn't:**
  - repo-cli's check script never type-checks its tests, so a forced local check was a false green (#2009).
  - Codex reports timed sandbox runs under heavy parallel load; their "+96%" slowdowns did not reproduce.
  - Bun fork pools time out in the Codex sandbox; only thread pools ran there.
- **Frustrating:**
  - A regex literal with `\r\n` and ` ` written through the Edit tool came out garbled on disk. It had to be rewritten from Python with explicit escapes.
  - fallow 3.34.1 changed glob semantics and red the dead-code cheap gate repo-wide for about an hour, until #1934 pinned 3.33.1 again.
- **Wished existed:** a census command that dedupes across check programs and groups by package and open-lane overlap. It was rebuilt in shell several times.

## Implementation improvement opportunities

- Hot scanners (ACP JSON, jsonc, toml, yaml, glob, git config) kept indexed character reads and module-level RegExps. An `Option` per character made the ACP strict scanner 5x slower in wave 4a, so this is a standing rule for parser code.
- The `@beep/yaml` stringify `indent` became a decoded non-negative integer (`IndentWidth`). `effect/String` `repeat` silently returns `""` for a negative count where native threw, so similar option-fed counts elsewhere should get the same schema treatment rather than a native escape.
- `@beep/utils` `replaceWith` and `replaceAllWith` now call `RegExp.prototype[Symbol.replace]` directly. A string search becomes an escaped RegExp, and `replaceAllWith` keeps native's TypeError for a non-global RegExp. This retired the last native callers instead of growing the closed directive allowlist.

## Lessons (confidence-tiered)

- **HIGH — Critical:**
  - Run `bun run beep quality test-tsgo` before any repo-cli final. The package's own check does not see test type errors, so a forced turbo check can be green while hosted Heavy / Check is red.
  - Never use `x[i] ?? ""` for an in-bounds read; use `Str.slice(i, i + 1)`. The fallback branch is unreachable, so the per-file branch ratchet and fallow complexity both fail.
- **MEDIUM — Best practice:**
  - Hold files that another active goal is editing, and agree an ownership list with that goal's owner. Effected 2c's list let 6d and 4c start the minute #2016 merged, with zero conflicts.
  - After pushing, take the final sha from `git rev-parse HEAD`. `gh pr view --json headRefOid` lagged behind the push once (#2018).
- **LOW — Consideration:** when a shared helper replaces several native searches, compare its edge semantics (negative index clamping) with each original call. `lastIndexOf` with a `fromIndex` clamps, but a prefix slice does not.
