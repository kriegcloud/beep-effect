# Reflection — review-verdict-envelope (2026-10-14, claude)

## Summary

The goal shipped one review envelope for every producer:
- `SourceRef` (a shared `TextQuote` plus a page-checked crop);
- the `ReviewItem` tagged union (six kinds);
- `VerdictRow` (`batchId`, `recordedAt`, a batch-scoped lock);
- `ReviewQueue` and `VerdictProjector` services, with S5 round-trip and property tests;
- the P0 spike evidence that decided the review pane;
- the amendment, delivered and applied by the `practice-claude-mod` owner (D15, D16, D22).

The verdict is complete. The one open item is the in-app Claude for Word run, which the operator
owns and which does not block anything.

## Tooling experience

- **Worked:**
  - Dev mods hot-loaded into the live desktop session gave real S1, S2 and S3 evidence on the
    operator's own Code tab in minutes.
  - Workflows that split contract, implementation, independent review and fix caught real defects
    before publish: an undo-rule contradiction, a tie-break order, a record/lock race, and a test
    Layer on the production path.
- **Didn't:**
  - Button press handlers in the spike pane failed silently.
  - Render-time state writes are denied.
  - Both cost operator round trips.
- **Frustrating:**
  - GitHub GraphQL budget exhaustion broke `yeet ready`, which then reported "no open PR". The
    orchestrator flipped the PR with an App token.
  - The detached readiness monitor that publish re-submits spends the same budget.
- **Wished existed:**
  - a way for a mod to report a button press's success or failure to the agent;
  - a REST-only path for `yeet ready`'s PR lookup.

## Implementation improvement opportunities

- Producers should render passage-region crops server-side. The mod cannot transcode images (it
  has no DOM and no Node).
- `VerdictLog` needs a JSONL adapter in the plugin (practice-claude-mod D22), with a `v1` →
  envelope decode transform for rows already on the attorney's PC.

## Goal & prompt critique

- The graduated SPEC should have specified the projection value, the batch-scoped lock and the
  text-read S3 gate. All three surfaced only in review. Proposed edit for future envelope-style
  SPECs: add a "Persisted target vs projection" line, and require a "lock scope" field for any
  append-only log.
- The P0 acceptance criterion gated on page images (`get_preview_page`). The text read is the real
  gate; the SPEC now says so.

## TODOs worth codifying

- Note in plugin-authoring that `ui.render` cannot write state, and that results reach the agent
  through `command.run` context.
- Add a goals lint for a projection target that names a persisted entity.
- Record the desktop mod facts in the practice-claude-mod runbook.

## Lessons (confidence-tiered)

- **HIGH — Critical:** Measure UI surface limits (element caps, selection reads, link targets) with
  a throwaway spike before fixing schema fields. S3b alone turned "show the Box page" into
  "producers ship crops".
- **MEDIUM — Best practice:** Record every review-driven contract change as a Decision Log row with
  how to reverse it, so sibling owners (`practice-claude-mod`) can mirror it.
- **LOW — Consideration:** Keep one PR per goal phase group (P0 to P2 here) to limit hosted CI runs.
  Merge main once before pushing, and regenerate generated files on the merged tree.
