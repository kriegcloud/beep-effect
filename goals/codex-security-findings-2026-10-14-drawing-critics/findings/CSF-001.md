# CSF-001: Read\-only drawing critics bypass tool permission checks

- Severity: Low
- Codex ID: `commit:08744ebc989881918d74a6bac4e765a3`

## Public Summary

Grok and Claude drawing critics receive review packs and earlier model reports
as context. Their launch arguments bypassed permission checks while inheriting
the operator's local authority. A lower-trust document could ask a reviewer to
use host tools outside the intended read-only review. The analysis established
the unsafe launch configuration; it did not execute an end-to-end model exploit.

## Current-HEAD Validation

Confirmed on current source. The `criticInvocation` branches passed
`bypassPermissions` to Grok and Claude. The pack and prior-report flow carries
untrusted prose into their prompts, and the subprocess is spawned directly.
Prompt instructions and an empty MCP configuration did not constrain built-in
file or shell tools. Disposition: `remediate`.

## Remediation

Grok now uses a strict filesystem sandbox, a deny-by-default permission mode,
explicit Read and Grep grants, and no web tools, memory, subagents, Bash,
Edit, or MCP tools. Claude uses restricted mode with only Read available and
denies unapproved prompts. The reviewer hint no longer asks Claude to run Bash.
Focused tests assert the enforced launch arguments and absence of permission
bypass. The installed CLI help and official vendor permission documentation
were checked; no paid model invocation was required.

- `packages/tooling/tool/cli/src/commands/Drawings/Drawings.critics.ts`
- `packages/tooling/tool/cli/test/drawings-critics.test.ts`
