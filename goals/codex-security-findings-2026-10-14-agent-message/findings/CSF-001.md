# CSF-001: Managed delivery bypasses recipient conversation grants

- Severity: Medium
- Codex ID: `commit:37aa2327ce1c8191b9c6eb3f88d6d0db`
- Source commit: `479c53e3878946215c957aee54346e9e2a12a32d`
- Owner: `@beep/repo-cli` managed native agent-message receiver
- Status: validated; remediation implemented, awaiting hosted proof and merge

## Public Summary

The managed receiver checked endpoint ownership, generation and policy before
submitting a queued envelope to the native model, but did not check the
receiver's persisted conversation grant. A sender with a valid grant for a
different conversation could queue content for this endpoint, expanding the
receiver's context beyond its authorized conversation.

## Current-HEAD Validation

Verdict: reproducible at the captured source revision and current base.
Disposition: remediate. The `serve` path submitted a claimed envelope after
checking only endpoint binding and policy fingerprint. The native prompt was
reachable without a receiving-grant check; the focused test queues an
out-of-scope conversation from a legitimately granted sender and confirms it
would otherwise reach that path.

## Remediation

Require a private host-issued receiving grant when starting managed `serve`.
Check its enrollment identity before launching the worker, register and validate
it with the mailbox store, and revalidate its endpoint, repository, sender and
conversation scope before each native prompt. An unauthorized claim returns a
definite failed receipt, allowing the queue to continue without ambiguity hold.
