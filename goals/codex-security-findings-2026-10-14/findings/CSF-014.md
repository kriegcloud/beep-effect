# CSF-014: Backdated commits bypass the new merge review window

- Severity: Low
- Codex ID: `commit:be07dc0f3b048191beaa21ebd6e777c9`
- Source commit: `3c65e30092285e15ed600470ccc29538c11c2f4a`
- Owner: Yeet REST merge review window
- Status: confirmed; repair implemented

## Public Summary

The REST merge gate measured its review delay from a PR head's committer date.
A contributor can backdate that metadata and push new content to an already
ready PR, making the gate treat the new head as if reviewers had seen it for
the full window. Other checks and the pinned-head merge still apply.

## Current-HEAD Validation

Verdict: confirmed narrow policy bypass. Security Cloud traced the current
REST field and gate calculation and demonstrated backdated metadata surviving
a push to a local receiver. The current checkout still used the untrusted
committer date. No live GitHub merge was attempted.

## Remediation

The REST gate now anchors the head time to GitHub check-suite creation and
the latest force-push timeline event, whichever is later, following the
repository's existing review-window policy. Missing or unreadable receipt
evidence cannot open the gate. The pure gate and REST fixtures cover a newly
received head despite old readiness and the relevant server timestamps.
