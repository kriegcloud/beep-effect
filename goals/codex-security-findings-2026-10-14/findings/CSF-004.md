# CSF-004: Crafted attachment names persistently block mail tagging

- Severity: Medium
- Codex ID: `commit:bc974bf0f854819185f94fd4a4b736a6`
- Source commit: `0f5b4d5ae1235eaedcb7d633ae4e62fb04d4237f`
- Owner: mail attachment filing
- Status: confirmed; repair implemented

## Public Summary

A recognized sender can reserve both deterministic names offered for an
attachment. A later upload then fails every create-only attempt, and the
mail-tagging job retries that message before its tag and page checkpoint are
recorded. The same collision can block later messages on every run.

## Current-HEAD Validation

Verdict: confirmed for the wired mail-tagging core under its create-only
DocumentStore contract. Security Cloud validation supplies a three-message
collision sequence without a hash collision; the current filer still tried
only the original and short-hash names and raised a fatal error on exhaustion.
The existing focused test reproduced the repeatable failure in an in-memory
contract-compliant store.

## Remediation

After all candidate names are durably abandoned in the filing ledger, the
filer now records an explicit `name-held` attachment skip and lets the message
settle. The abandonment records retain message and attachment identities for
operator follow-up. Other attachment and message processing can advance.
