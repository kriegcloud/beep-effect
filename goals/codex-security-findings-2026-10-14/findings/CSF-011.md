# CSF-011: Source checkout preloads can forge signed pilot evidence

- Severity: Low
- Codex ID: `commit:6b1c901199b88191acb574eb229b6334`
- Source commit: `28b28fa551a4aa30c3cfd5b5a3a899a739328aa2`
- Owner: signed cache pilot supervisor
- Status: confirmed; repair implemented

## Public Summary

A signed cache pilot can run against a source checkout separate from the trusted
worker checkout. Bun was started with that source as its working directory and
could load its `bunfig.toml` preload before the trusted worker. An attacker
controlling the source checkout could forge a plausible pilot report in the
writable supervisor directory. This threatens authenticated measurement
integrity; the report did not show host escape or issuer-key disclosure.

## Current-HEAD Validation

Verdict: confirmed at current HEAD. The supervisor passed no explicit Bun
configuration. Security Cloud demonstrated source-controlled preload execution
with Bun 1.2.14, and the code path accepted a separate source checkout. The
full signed envelope was not reproduced there. A local Bun 1.4.2 experiment
confirmed the startup primitive and the exact safe flag shape.

## Remediation

The supervisor writes an empty trusted Bun configuration beside its worker and
passes it using `--config=<absolute-path>`. An isolated Bun 1.4.2 check showed
that this exact form suppressed a source-controlled preload and ran the worker.
The space-separated `--config <path>` form did not, so the argument shape is
checked explicitly in the supervisor test.

Changed files:

- `packages/tooling/tool/cli/src/commands/Cache/Cache.pilot.runner.ts`
- `packages/tooling/tool/cli/test/cache-signed-runner.test.ts`

## Verification

- The signed-runner test suite passed (18 tests), including explicit trusted
  config path and content checks.
- Bun 1.4.2 isolated startup check: default loaded the source preload;
  `--config=<trusted path>` did not and ran the worker.
