# CSF-017: Correspondent parser allows CPU\-exhausting regex backtracking

- Severity: Low
- Codex ID: `commit:ed75e1347d0c8191b18a4dfbfba086b7`
- Source commit: `cf106e28a726acb68430a5aa6a15260dc346ba5f`
- Owner: practice KG correspondent parser
- Status: confirmed; repair implemented

## Public Summary

An unanchored correspondent address regexp let its display-name and whitespace
quantifiers overlap. A long malformed header with no `<` caused repeated
backtracking before correspondent lookup could reject the input. The same
parser handled imported email metadata.

## Current-HEAD Validation

Verdict: confirmed at current HEAD. Security Cloud reproduced multi-second
matching with 2,048 and 4,096 spaces using the committed expression. The
lookup path parsed before validating its address count. The reproduction was
parser-level, not a complete MCP invocation.

## Remediation

The parser now separates entries with a linear scan that respects quoted
commas, then applies anchored address patterns to each entry. It rejects
oversized headers before parsing. The lookup tests retain supported bare,
quoted, named, and comma-separated address forms and include the malformed
4,096-space input.

Changed files:

- `packages/law-practice/server/src/PracticeKg.correspondents.ts`
- `packages/law-practice/server/test/PracticeKg.correspondents.test.ts`

## Verification

- The focused correspondent lookup test passed, including the long malformed
  header regression.
