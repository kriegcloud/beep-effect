# CSF-021: Predictable codemod staging paths allow symlink file overwrite

- Severity: Informational
- Codex ID: `commit:16f7894e857c8191b3aefbc545ed1f19`
- Source commit: `7cc0aa9b332feaf6ace8c6f6c7589f28aa5bfba1`
- Owner: schema-parity codemod staging
- Status: confirmed; repair implemented

## Public Summary

The codemod wrote planned text to a predictable adjacent staging pathname
without exclusive creation. A planted symlink at that path could overwrite a
writable file outside the checkout when an operator selected `--write`.

## Current-HEAD Validation

Verdict: confirmed at current HEAD. `applyPlannedWrites` used a fixed stage
suffix and ordinary `writeFileString`; its cleanup could also remove a
pre-existing staging entry after a failed write.

## Remediation

Give every stage a cryptographically random name, create it exclusively with
`wx`, and clean up only files this run successfully created. A regression
plants the old predictable symlink and verifies the outside sentinel and link
remain untouched while the source rewrite succeeds.
