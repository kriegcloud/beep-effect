# CSF-009: Tesseract file\-list input bypasses the corpus read boundary

- Severity: Low
- Codex ID: `commit:2472aaabc8c881918d7d3de7ece3993a`
- Source commit: `2dffb2827cd4a07a8b571c1d4f765f61410b81f3`
- Owner: corpus OCR raster intake
- Status: confirmed; repair implemented

## Public Summary

An image-named corpus source could contain a list of readable host paths rather
than raster bytes. The OCR path passed the original bytes to native Tesseract,
whose image input can also act as a filename list. This could make an opt-in
local extraction read images outside the intended corpus root and persist their
recognized text in extraction artifacts.

## Current-HEAD Validation

Verdict: confirmed at current HEAD. The source-path containment check applied
to the catalogued file, but the PNG/JPEG/TIFF OCR path selected by extension
passed its bytes through without decoding. The report traced the complete
boundary crossing; native Tesseract execution was unavailable in its review
container, so that behavior remains a stated precondition rather than a
demonstrated data leak.

## Remediation

Before planning an image for OCR, the corpus extractor now decodes it with a
bounded pixel limit and re-encodes a fresh PNG. A filename list cannot survive
that conversion; malformed raster input is not submitted to Tesseract. The
page image digest reflects the normalized bytes.
