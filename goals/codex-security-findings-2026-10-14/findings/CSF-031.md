# CSF-031: Undo can delete calendar entries verified after planning

- Severity: Informational
- Codex ID: `commit:678a13c732d881918b51a7aee1910268`
- Source commit: `f443286f26afd5b6df804b2bfbdfacaa71dbb022`
- Owner: docket undo and M365 event writes
- Status: confirmed; repair implemented

## Public Summary

Docket undo planned deletion after reading provisional event categories, then
deleted the event by ID without rechecking categories or binding deletion to a
version. A calendar editor could verify or recategorize an event after planning
and still lose it during an authorized undo.

## Current-HEAD Validation

Verdict: confirmed at current HEAD. The planned action retained only the ID;
the apply path sent an unconditional Graph DELETE. The route requires an
authorized operator and calendar access, but the data preservation rule still
applies to concurrent edits.

## Remediation

Read categories again immediately before deletion. Keep events that are no
longer exclusively provisional or lack a usable change key. Send the fresh
change key as `If-Match` so another edit between that read and deletion causes
Graph to reject the write. Existing callers can still issue an unconditional
delete where that is their explicit contract.
