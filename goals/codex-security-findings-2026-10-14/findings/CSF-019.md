# CSF-019: Repository\-controlled ignore globs can hang Graft via ReDoS

- Severity: Informational
- Codex ID: `commit:0faeb689284081918ca7eb9a6da29805`
- Source commit: `3f4b0b6cb66960fb69016f828bf71075447f4180`
- Owner: Graft deep-ignore patch
- Status: confirmed; repair implemented

## Public Summary

A repository-controlled `.graftignore` rule reached a dynamically built regular
expression. Overlapping wildcards could force excessive backtracking during
deep-ignore matching on ordinary repository paths.

## Current-HEAD Validation

Verdict: confirmed at current HEAD. The current 0.21.1 dist patch still
compiled repository-controlled glob rules to regular expressions with overlapping
repetition. The installed matcher used that patch; the report cited an older
version, but the same sink remained present.

## Remediation

Replace regex compilation in the versioned Graft patch with a memoized glob
matcher. Its states are indexed by pattern token and path position, so
overlapping wildcard choices cannot cause exponential revisits. Preserve the
supported anchored, nested, `*`, `**`, `?`, and trailing-directory semantics.
The installed workstation copy was updated from the patch after saving its
previous bytes to a local backup.

Changed files:

- `scripts/graft/patches/0.21.1/util-deep-ignore.patch`
- `scripts/graft/tests/deep-ignore.test.mjs`

  Graft 0.21.1 after the local update.
