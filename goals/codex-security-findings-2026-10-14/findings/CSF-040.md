# CSF-040: Cursor shell deny guard can be bypassed with pathname globs

- Severity: Informational
- Codex ID: `commit:d60503208ce88191b1ea6c0c734ba873`
- Source commit: `fd7d06b834b4f98ae3196354f707044824cdac90`
- Owner: Cursor shell guard
- Status: confirmed; repair implemented

## Public Summary

The Cursor beforeShellExecution guard compared literal executable words while the downstream shell expanded pathname globs. A command spelling such as /usr/bin/g[i]t could therefore be allowed by the hook and run Git.

## Current-HEAD Validation

Verdict: confirmed at current HEAD. The current hook rejected dollar expansion but accepted bracket, star, and question-mark globs. A local hook fixture confirmed that the globbed Git command received allow before the fix.

## Remediation

Reject commands containing pathname glob syntax in the guard and document the conservative literal-command policy. A hook fixture now denies the globbed Git spelling and still permits a plain command.

Changed files:

- `.cursor/hooks/deny-shell.sh`
- `docs/runbooks/agent-pools.md`

## Verification

- `Python JSON-payload fixture for the configured shell hook: globbed Git denied, plain echo allowed, literal Git denied` passed.
