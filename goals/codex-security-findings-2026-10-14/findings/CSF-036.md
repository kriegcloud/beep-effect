# CSF-036: Unsafe shell quoting in PR\-title recovery commands

- Severity: Informational
- Codex ID: `commit:93d6eaa8645881919f32769efac1dadf`
- Source commit: `5479af40a41788fc2b8014ff658e4eed8da4b3a4`
- Owner: Yeet PR title recovery
- Status: confirmed; repair implemented

## Public Summary

On a PR title rename failure, Yeet printed a runnable shell command containing an untrusted commit-derived title inside double quotes. Shell substitutions could execute when copied.

## Current-HEAD Validation

Verdict: confirmed at current HEAD. The current publish path used argument arrays for its own GitHub requests, but both recovery messages interpolated the title into shell text. A failure during PR rename made that text visible to an operator.

## Remediation

Replace both runnable recovery commands with a GitHub title-edit instruction that includes no untrusted title bytes. A regression uses a command-substitution title and asserts it is absent from the failure message.
