# CSF-001: Crafted review counts can crash Yeet closeout and monitoring

- Severity: Medium
- Codex ID: `commit:4219f7291acc8191aab10fe5ae352a3c`
- Source commit: `661e0932de3a5a04797bfa4d6a80552f317429cf`
- Owner: Yeet review body parsing
- Status: confirmed; repair implemented

## Public Summary

A public pull request reviewer can submit an oversized Greptile-style finding
count. Yeet parses that untrusted review body during closeout and monitoring;
the count can overflow to `Infinity` and throw at checked schema construction,
repeatedly interrupting the PR workflow.

## Current-HEAD Validation

Verdict: confirmed vulnerable at the captured branch head. The Security Cloud
validation and attack-path analysis identify the review-submission boundary,
the overflowing decimal conversion, and the closeout/monitoring consumers.
Current source still accepted overflowing numeric captures. The regression
case exercises a 400-digit count through the actual parser and verifies that
advisory parsing completes after the repair.

## Remediation

The parser now saturates individual counts and accumulated tallies at a finite
ceiling before constructing checked review-body models. Oversized values
remain visible as advisories without interrupting closeout or monitoring.
