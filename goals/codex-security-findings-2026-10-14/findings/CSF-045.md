# CSF-045: Chunked uploads commit swapped sources before checking integrity

- Severity: Informational
- Codex ID: `commit:f1b30bf8b93c8191ade97dae73ebb689`
- Source commit: `98c3947d44359fd230a9adfb082268847e3174fb`
- Owner: Box content migration
- Status: confirmed; repair implemented

## Public Summary

The migration verified a source pathname against its reviewed plan, then
reopened it for chunked upload. A same-size file or symlink swap in between
could publish unapproved bytes to Box before its returned SHA-1 exposed the
mismatch. The existing error receipt left that remote item in place.

## Current-HEAD Validation

Verdict: confirmed at current HEAD. The chunked route had no precommit digest
check and reopened a mutable pathname after plan validation. The attack needs
write access to the source entry during migration.

## Remediation

Copy each chunked source to a private scoped file, verify the staged size and
SHA-256 against the reviewed plan, and stream only that copy. Reject changed
sources before opening an upload session. Scoped cleanup runs after Box has
consumed the stream. Single-request uploads retain their existing provider
digest check.
