# CSF-050: Verdict export lacks symlink protection for its output file

- Severity: Low
- Codex ID: `commit:26190290755c81918cb7cb4935b8f079`
- Source commit: `c2848918b71c41a77bae1cb63eb919b7c94a56d1`
- Owner: Practice Claude mod verdict export
- Status: remediated locally; merge and cloud closure pending

## Public Summary

`/practice export` passed a fixed filename in the session working directory to the mod engine's opaque `fs.write` call. The plugin could not require a no-follow open or atomic replacement, so a workspace symlink could redirect the write if that engine follows symlinks.

## Current-HEAD Validation

**Real boundary risk, medium confidence.** The engine's filesystem implementation is unavailable, so symlink-following behavior was not proven by a live exploit. The current source did use a predictable workspace path without a no-follow guarantee. The plugin can avoid that write entirely.

## Remediation

The command now returns the JSONL rows for explicit saving by the user. The verdict service no longer writes an export file, and the mod host no longer exposes a filesystem-write operation. Reversal: restore direct file export only after the engine exposes a tested no-follow, atomic write API.
