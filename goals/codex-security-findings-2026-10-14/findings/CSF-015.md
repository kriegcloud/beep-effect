# CSF-015: Address substring parsing bypasses attachment sender restrictions

- Severity: Low
- Codex ID: `commit:ce6dcbeec7d08191948f80256a4a678f`
- Source commit: `1a4aa495f845423178258e62a78a283416863451`
- Owner: mail sender address normalization
- Status: confirmed; repair implemented

## Public Summary

The mailbox adapter used a helper that extracted the first angle-bracketed
substring from a provider address. A quoted local part can contain such a
substring while the actual address belongs to another domain. If Graph
preserved the spelling, the adapter could classify attacker mail as trusted
sender correspondence and make an attachment eligible for filing.

## Current-HEAD Validation

Verdict: confirmed parser identity-substitution defect at current HEAD. The
helper searched for any `<...>` fragment before schema validation, so the
validated identity need not represent the whole input. The report proved the
expression behavior and downstream path but did not establish that Microsoft
365 preserves the crafted address in a delivered message.

## Remediation

The header-form pattern now consumes the entire trimmed input. A bracketed
fragment inside a quoted local part with a trailing domain no longer becomes
the sender identity. Existing quoted and `Name <address>` cases remain
supported.

- `packages/law-practice/server/test/MailTagging.mailbox.test.ts`
