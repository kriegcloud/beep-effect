# CSF-006: Review checkpoints expose mail content through permissive files

- Severity: Low
- Codex ID: `commit:0df06ede67a0819192f96233f81e711d`
- Source commit: `d413c39afe6e3c53ddf9d2727ae207cf251e5f00`
- Owner: docket intake file store
- Status: confirmed; repair implemented

## Public Summary

The docket review checkpoint persists source-bearing text, including citations
and matter references. Its state directory and atomic replacement files were
created with umask-dependent permissions, which can expose this data to another
local account when path ancestors are traversable.

## Current-HEAD Validation

Verdict: confirmed conditional local disclosure. Security Cloud traced the
normal checkpoint path to directory creation and an unrestricted temporary
file open. Current HEAD retained those options. A private ancestor or umask
would prevent cross-account reads, but the store did not enforce either.

## Remediation

The store creates and tightens its state and digest directories to owner-only
access and creates atomic replacement and lock files with owner-only modes.
The service-unit example also sets a restrictive umask. Existing state inside
the configured directory becomes inaccessible to other local accounts when
the live store starts.
