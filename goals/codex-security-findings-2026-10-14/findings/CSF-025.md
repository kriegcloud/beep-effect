# CSF-025: Artifact upload allows command execution through zip filenames

- Severity: Informational
- Codex ID: `commit:4aa0ea969fe88191ab0f795b83db7147`
- Source commit: `7929b1f529759c823571d90423d9aaa5afbcbbb8`
- Owner: scratchpad artifact archive command
- Status: already fixed at current HEAD

## Public Summary

The original POSIX artifact upload command passed relative filenames to
Info-ZIP without ending option parsing. A root-level file beginning with `-`
could be interpreted as an option, including zip's command-running archive
test option. This was a local upload API path requiring attacker-influenced
filenames; the report did not establish an existing production caller.

## Current-HEAD Validation

Verdict: already fixed at current HEAD. The current `zipCommand` constructs
`zip -<level> -qr <destination> -- <files...>`, so leading-dash filenames
follow the option terminator as literal operands. Git blame attributes the
terminator to commit `58766950c5`, later than the reported source commit.
The current scratchpad test explicitly covers `-h`, `--help`, and a nested
leading-dash path.

## Remediation

No new code change is needed for this finding. Close it as fixed only after
the packet PR merges and the current-head proof remains valid.
