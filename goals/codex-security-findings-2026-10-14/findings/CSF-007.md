# CSF-007: Mail\-tagging state can be readable by other local users

- Severity: Low
- Codex ID: `commit:0f13c54587308191b9ea7187f7632ccc`
- Source commit: `6008faca1d0927aa2aed947e23cbf203a34629ae`
- Owner: mail-tagging state and lock
- Status: confirmed; repair implemented

## Public Summary

Mail-tagging ledgers hold message, matter, folder, and attachment identifiers.
The writing command's state lock and the file adapter created the directory
and ledger files with umask-dependent modes, allowing a different local user
to read metadata when ancestors are traversable.

## Current-HEAD Validation

Verdict: confirmed conditional local disclosure. Security Cloud traced the
writing command through the lock and ledger adapters; the current checkout
still created the directory and files without restrictive modes. Protected
ancestors or an existing restrictive umask prevent the read, but are not
enforced by the application.

## Remediation

The writer lock and file adapter now create owner-only state directories and
files, tighten pre-existing state paths before writing, and the sample user
service sets `UMask=0077`. Attended commands use the same permission controls.

- `apps/practice-mail-tagging/src/PracticeMailTagging.lock.ts`
- `apps/practice-mail-tagging/deploy/practice-mail-tagging.service`
- `packages/law-practice/server/src/internal/MailTaggingStateFile.ts`
- `packages/law-practice/server/test/MailTagging.files.test.ts`
