# CSF-051: Untrusted PR comments can forge bot\-published replay verdicts

- Severity: Low
- Codex ID: `commit:e5b6e1a72814819185018866128e5f74`
- Source commit: `8858e31070d5fac12533818b6a6fdbb2a32f905f`
- Owner: Skills update train replay attribution
- Status: remediated locally; merge and cloud closure pending

## Public Summary

The weekly skills update issue selected the newest valid replay marker from any PR comment. An ordinary commenter could post a later marker with a clean replay and make the issue display that forged verdict.

## Current-HEAD Validation

**Confirmed.** The current renderer sorted every comment by creation time and parsed markers without checking the author or PR head. The forged comment affected the published tracking issue; it did not change the replay or relock gates.

## Remediation

The replay workflow binds its sticky comment to the pull request head SHA and updates only the `github-actions[bot]` comment. The issue renderer accepts a marker only from that bot and only for the current head. Reversal: replace the comment channel with an authenticated artifact or check-run lookup while preserving both identity and head binding.
