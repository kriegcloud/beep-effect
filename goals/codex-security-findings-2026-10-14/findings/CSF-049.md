# CSF-049: Materialize follows install symlinks outside the repository

- Severity: Informational
- Codex ID: `commit:ed2f3eb6d7e081919206b070a79dce1c`
- Source commit: `4e66575c646c282169021a6d5eb3d01129617bcf`
- Owner: Skills materializer target containment
- Status: repair implemented; repository verification pending

## Public Summary

The skill materializer accepted an install target whose parent directory was a
symlink outside the repository. Its physical target resolver followed the link,
then staged and replaced the external skill directory. Cleanup could remove the
previous external directory, while post-write checks still followed the same
link and reported success.

## Current-HEAD Validation

Confirmed vulnerable at the pre-fix branch head. The authenticated report
traces the allowed textual target through `physicalTargets` and
`publishSkillTree`; neither bounded the resolved parent to the physical
repository root. The local regression redirects the skills parent to an
external directory and confirms a write attempt is refused before publication.

## Remediation

Resolve the repository root and the existing parent of each install directory.
Reject any resolved parent outside that root and require the physical install
directory to be one of the repository's two permitted skills directories before
staging, renaming, or cleanup. The normal in-repository mirror symlink remains
supported.
