# CSF-002: Credential\-bank regex enables small\-input denial of service

- Severity: Medium
- Codex ID: `commit:4ca94a9561648191a4298e2e9910ef54`
- Source commit: `494d134760689cb62c222172bcd037be618b4a9a`
- Owner: canonical credential pattern bank
- Status: confirmed; repair implemented

## Public Summary

An attacker-controlled text field with a long sequence of assignment-like key
characters can force the credential bank's secret-assignment regex into repeated
backtracking. The same canonical rule is used by detection, counting, and
replacement, so one small input can stall multiple security and observability
paths.

## Current-HEAD Validation

Verdict: confirmed vulnerable at the captured branch head. Security Cloud
validation and attack-path analysis identify a 4 KiB `key-` sequence as a
multi-second trigger and trace it through the canonical bank's three public
operations. Current source retained the ambiguous prefix and keyword regex.
The regression now runs all three operations on that input in the normal test
timeout and checks that a nested secret assignment is still recognized.

## Remediation

The assignment grammar now recognizes candidate key tokens with a linear
character class, then classifies their captured key against the credential
keyword set. Candidate matches without a credential keyword are discarded.
This removes the ambiguous regex prefix that caused backtracking while keeping
the shared bank's detection, counting, and replacement behavior aligned.
