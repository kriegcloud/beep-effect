# CSF-010: Mail attachment names inject terminal controls during intake

- Severity: Low
- Codex ID: `commit:69197f0ffd2c8191809faec14eb0315a`
- Source commit: `08fb0d175463dc86ee6243ce5747bcff59ac0971`
- Owner: drawing intake terminal summary
- Status: confirmed; repair implemented

## Public Summary

An external sender's attachment name could reach the operator's intake summary
without terminal escaping. Inline and duplicate attachments lack a saved
filename, so their display name fell back to the original Graph value. A
control-bearing name could clear or rewrite an interpreting terminal display
when the operator runs intake.

## Current-HEAD Validation

Verdict: confirmed at current HEAD. The Graph name schema permits control
characters; row construction preserves the original value, and the summary
printed skipped or duplicate names directly. Security Cloud reproduced the
formatter in isolation; live Graph preservation of the crafted name was not
tested and remains a condition of exploitation.

## Remediation

The terminal summary replaces control and format characters in display names,
including duplicate references. The durable JSON provenance record retains the
original attachment name for audit.

Changed files:

- `packages/tooling/tool/cli/src/commands/Drawings/Drawings.intake.ts`
- `packages/tooling/tool/cli/test/drawings-intake.test.ts`

## Verification

- Two focused drawing-intake tests passed. They check that the JSON record
  retains the original name while printed output contains no escape byte.
