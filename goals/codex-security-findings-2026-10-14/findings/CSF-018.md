# CSF-018: Backslash filenames escape scorer staging and enable code execution

- Severity: Informational
- Codex ID: `commit:0086d4ff9304819189a558c785368663`
- Source commit: `2476ffa8c9a6115013a84a489fe33a57a0ce80bb`
- Owner: agent effectiveness law-lane staging
- Status: confirmed; repair implemented

## Public Summary

On POSIX, a backslash can be part of a filename. The scorer normalized
backslashes in fixture filenames to `/` for display, then reused the result
as a filesystem path during law-lane staging. A crafted file name could thus
turn into `../` traversal and overwrite files outside the scorer sandbox
before a trusted CLI entrypoint was launched.

## Current-HEAD Validation

Verdict: confirmed at current HEAD. Source snapshots normalized a relative
filename, and `prepareLawSandbox` joined that value to its source and staging
roots without canonical containment checks. Security Cloud reproduced the
path transformation without writing the exploit payload; full scorer
execution was not tested there.

## Remediation

Before each copy, the law lane now resolves both the source and destination
through the shared canonical root-containment guard. A path that escapes
either root fails before staging. The regression creates a literal
backslash-bearing source filename, confirms its normalized relative path, and
checks that the law lane rejects it.
