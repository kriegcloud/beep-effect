# CSF-047: Provenance outputs follow symlinks outside the corpus root

- Severity: Informational
- Codex ID: `commit:f681d44162a08191983edce900c3fb56`
- Source commit: `604694ebec1d37241d36cf21dbf2833448af1a57`
- Owner: Corpus provenance output
- Status: confirmed; repair implemented

## Public Summary

The provenance workflows checked their output directory but passed unchecked child paths to ordinary write and append calls. A planted metadata.jsonl symlink could truncate an operator-writable file outside the corpus.

## Current-HEAD Validation

Verdict: confirmed at current HEAD. Current HEAD joined fixed output leaf names after parent validation and wrote them without final-component symlink protection. The metadata workflow reached its truncate before invoking the external reader.

## Remediation

Create and recheck the canonical output directory, bind each write to that directory descriptor, atomically replace complete output files, and append only through no-follow descriptors. A metadata symlink regression confirms the outside target remains unchanged.
