# CSF-012: Hook resolver executes code from an untrusted current checkout

- Severity: Low
- Codex ID: `commit:ab3071e2c0b48191a525ffe717ae2e8a`
- Source commit: `650a025a72e7529ff801ba184f1fd08f91c95a71`
- Owner: Claude hook executable root
- Status: confirmed; repair implemented

## Public Summary

The shared Claude hook settings selected executable shell and Node files from
the current Git checkout whenever it contained `.claude/hooks`. A session
retaining trusted settings could therefore execute an attacker checkout's
replacement hooks after changing working directory.

## Current-HEAD Validation

Verdict: confirmed at current HEAD. Twenty-one hook commands in the current
settings used the Git root and directory existence as an executable trust
decision. The launch project's `CLAUDE_PROJECT_DIR` was overwritten.

## Remediation

Keep hook executables in the session's launch project. With no valid launch
root, skip the hook. Update the recovery runbook to require a fresh session
when another checkout's hooks are needed. A regression runs the configured
shell and Node commands from a crafted checkout and observes only trusted
fixtures.

- `.claude/settings.json`
- `docs/runbooks/graft-local-recovery.md`
- `packages/tooling/tool/cli/test/claude-hook-root.test.ts`
