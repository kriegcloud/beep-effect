# CSF-013: Aliased packages bypass the exact\-version Bun audit ignore guard

- Severity: Low
- Codex ID: `commit:b90b7e5053848191b94e681ebcef3438`
- Source commit: `f7d91408be3ac2fb4ec3de0da407f1b74e5d87a8`
- Owner: Bun audit OSV override selection
- Status: confirmed; repair implemented

## Public Summary

The local Bun audit mirrored an exact package-version exception into an
advisory-wide ignore. Its guard selected lockfile entries by their keys, so
an alias resolving to another version of the same package could be overlooked
and the broader ignore applied. The checked-in lockfile did not contain the
reported alias; a later dependency update could introduce one.

## Current-HEAD Validation

Verdict: confirmed at current HEAD. Bun lockfile aliases can use a different
key from the resolved package identity, and the guard ignored their tuple
value unless the key matched. Security Cloud reproduced the predicate gap
offline; an end-to-end Bun audit was not run there. The separate OSV scan
remains an additional control.

## Remediation

Select every lockfile tuple whose resolved identity names the package, as
well as key-matched tuples, before permitting the advisory-wide ignore.
Root and nested alias regressions now refuse a mixed-version lockfile; an
alias resolving to the reviewed version remains permitted.
