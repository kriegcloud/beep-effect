# CSF-048: Unbounded LCS allocation enables skill\-review denial of service

- Severity: Low
- Codex ID: `commit:e9c4b8dbfb9c819188c33e36b3bea73c`
- Source commit: `08fa45bd98cacd178c6214259aaf4c4b0c23f865`
- Owner: Skills provenance patch rendering
- Status: repair implemented; repository verification pending

## Public Summary

Repository-controlled skill text could cause the read-only provenance and lock
planning commands to allocate a quadratic longest-common-subsequence table.
The report measured a roughly 2 GB table request from a roughly 1 MB input and
an out-of-memory failure from a larger input. The relevant path remains reachable
when the installed skill targets agree and pinned upstream retrieval succeeds.

## Current-HEAD Validation

Confirmed vulnerable at the pre-fix branch head. The authenticated report traces
the installed skill read through `renderModifiedFilePatch` to `lcsTable`, and the
source had no allocation or work bound. The report's focused reproduction used
an exact extracted calculation because its scanner checkout lacked dependencies;
the local service regression now runs the repository implementation with a
100,001-newline skill and verifies a typed refusal before hunk generation.

## Remediation

Limit review hunks to 100,000 combined input lines with a `SkillsCommandError`.
For smaller inputs, trim identical prefixes and suffixes, then limit the LCS
matrix to four million cells. Larger changed regions use a valid linear-size
whole-region replacement hunk. This keeps ordinary skill patch reviews usable
without a quadratic allocation.
