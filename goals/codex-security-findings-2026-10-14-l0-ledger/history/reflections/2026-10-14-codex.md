# Reflection — codex-security-findings-2026-10-14-l0-ledger

## Summary

Two new Security Cloud findings were confirmed, repaired, merged in PR #1805,
and observed Fixed. The signed-in open view showed zero findings. The packet
is retained with exact IDs and merged-revision evidence.

## Tooling experience

- **Worked:** CSV ingest kept raw details ignored; focused service tests
  exercised both root causes; Yeet pinned the merge to the reviewed head and
  reread threads.
- **Didn't:** The old reviewer host emitted a short-head check association
  while the branch's new gate required PR, full head, and base. The repo
  worktree sweeper did not own the app-managed checkout.
- **Frustrating:** Hosted coverage and lint policy jobs remained pending after
  all 16 required checks were green. S11 recorded the pending jobs at merge.
- **Wished existed:** A rollout helper that rebinds a same-head, independent
  reviewer result to a newly required association with explicit provenance.

## Implementation improvement opportunities

- Add a reviewer migration check that detects legacy `external_id` before a
  PR reaches its merge window. Keep the gate strict; migrate the check.
- Keep the PR/base change tests in the service and merge-gate fixtures so
  future check reuse cannot silently return to head-only authorization.

## Goal & prompt critique

The launcher correctly required exact Cloud IDs and post-merge closure. Its
proof step should explicitly distinguish required hosted checks, optional
jobs, and full local verification under the push-first Yeet workflow.

## TODOs worth codifying

- Add reviewer association migration instructions to the reviewer runbook.
- Add an app-managed worktree retirement path to post-merge closeout.

## Lessons (confidence-tiered)

- **HIGH — Critical:** Bind an approval to the PR and base whose diff was
  reviewed; a shared head alone cannot represent that context.
- **MEDIUM — Best practice:** Exercise the exact merge gate before the review
  window ends, then retain its output with the closeout receipt.
- **LOW — Consideration:** Keep browser closure evidence as an untracked
  screenshot plus sanitized status receipt when the connector exposes no
  supported mutation tool.
