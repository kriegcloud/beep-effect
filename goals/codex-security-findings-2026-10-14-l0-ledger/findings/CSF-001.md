# CSF-001: Ledger symlinks can redirect review writes into shell startup files

- Severity: High
- Codex ID: `commit:96a19c513cd88191afbb9eb66cc5c7c5`
- Source commit: `5169ea9584cbadb2d4bc182495c8577b842531cf`
- Owner: Skills review and hunk ledger (`L1-ledger`)
- Status: fixed by merged PR #1805; exact Cloud ID observed Fixed

## Public Summary

The skills review decision path read and appended `.agents/skill-patches/ledger.jsonl`
through ordinary path operations. A contributor-controlled checkout could replace the
ledger with a symlink to an absent shell startup file. The existence check treated
that dangling link as an absent ledger, while the append followed it and created
the external file. Patch filenames flow into ledger rows; shell syntax in such a
filename would be retained if the redirected file were later sourced. This needs
a local operator to run the decision command and later source the target file.

## Current-HEAD Validation

Verdict: `confirmed-vulnerable`. Disposition: `remediate`.

Security Cloud's Validation and Evidence trace the symlink, resolving existence
check, append, and attacker-controlled filename path. Its isolated filesystem
probe established the redirection; it did not run the full CLI exploit. At
current HEAD, `readHunkLedger` used `fs.exists` and `appendHunkLedgerRows`
used an append flag on the same pathname. An existing nonempty invalid target
would fail row decoding, so the absent or empty target is material. The focused
service test now exercises a normal review decision, replaces the ledger with
a dangling link, and proves read and append fail without creating the target.

## Remediation

Bind the repository, `.agents`, and `skill-patches` directories to open
descriptors. Refuse symlinked ancestors and nonregular or multiply linked
ledger files. Open the final entry with `O_NOFOLLOW`, then verify the opened
inode before reading or appending. Missing directories and a missing ledger
retain their normal behavior. Unsupported descriptor binding fails closed.
