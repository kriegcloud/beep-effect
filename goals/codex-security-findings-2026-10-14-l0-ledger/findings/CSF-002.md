# CSF-002: L0 success can bypass review on another PR sharing its head

- Severity: Medium
- Codex ID: `commit:e99498e3438081918d9d598cbd94d26a`
- Source commit: `ed2612d8cdc96bd109905d47577e8b8c6b4263f5`
- Owner: Reviewer service and Yeet merge gate (`L2-reviewer`)
- Status: confirmed at current HEAD; remediation implemented; merge and Cloud closure pending

## Public Summary

A contributor can open two PRs with one head commit and different bases. One
diff contains code; the other contains only documentation. L0 classification
uses the selected PR's file list, but check reuse and merge validation used
only the head SHA and App identity. A successful documentation check could
therefore satisfy the reviewer gate for the code PR, even after a prior code
review failure if the documentation check was newer. A trusted reviewer must
process the stacked PR; the external controller's deployed triggers were not
available for validation. Independent merge requirements still apply.

## Current-HEAD Validation

Verdict: `confirmed-vulnerable`. Disposition: `remediate`.

Security Cloud's Validation and Evidence establish the PR/base input,
classification, check reuse/completion, and both Yeet merge gate call paths.
Its isolated Git fixture and source-fragment probe reproduce the gate result,
but not an end-to-end GitHub workflow because the scan environment lacked
dependencies. Current source independently confirms `start` reused any
in-progress App check on the head and `reviewerCheckSatisfied` chose the newest
successful App check on that head, without PR or base association. The local
HTTP harness now exercises service transitions and the predicate, including
the cross-PR success after a failure.

## Remediation

Bind every reviewer check to the exact PR number, 40-character head SHA, and
40-character base SHA in `external_id`. Reuse and complete only a check whose
association matches the current PR and base. Require that same association at
the merge gate and recheck both head and base after reading checks. L0
classification also rejects a base movement while it lists files.
The L0 command carries the classified base into check creation and rejects a
base change in the gap between those operations.
