# Reflection — literal-kit-subset-algebra (2026-10-22, claude)

## Summary

`LiteralKit` and `MappedLiteralKit` gained kit-returning `pick` / `omit`, `$match` became `match`, and `matchOrElse` arrived, with a typed dispatch miss and own-key lookup. A codemod migrated 323 reads and 24 re-wraps. `@beep/schema` dropped 466,896 → 398,630 single-checker instantiations and `@beep/law-practice-domain` 1,015,133 → 815,028; `match` dispatch fell from 79 to 7 ns. Three census amendments landed in the upstream-first doctrine, and two upstream Effect issues were filed (#9821, #9822). PR #2080.

## Tooling experience

- **Worked:** the schema-parity codemod engine (a new type-directed rule in about 200 lines, idempotent dry runs); `check-census --gate-only` with a same-compiler merge-base worktree for honest before/after numbers; `turbo run check --filter="...@beep/schema"` as the dependent sweep; the three-model panel plus `/grill-with-docs`, whose rulings held up under measurement.
- **Didn't:** the codemod's default roots skipped `infra` and `scratchpad`; `check-census --write-baseline` ignored newly registered targets; the Bash tool's Bun version tripped the pre-push hook.
- **Frustrating:** fallow attributed rename-rehashed clones as introduced, and `runPlanExecution` complexity from #2076 reds every lane that touches that function.
- **Wished existed:** a codemod mode that reports object-literal keys named like the renamed member.

## Implementation improvement opportunities

- `omit`'s result type is a rest tuple of the complement union, so `transform` on an omit-derived kit is positional over an unordered type (documented as a Gotcha). An order-preserving tuple filter, as proposed upstream in #9821, would remove the Gotcha.
- The two new tagged error classes cost about 1.4k instantiations per importer of the `LiteralKit` subpath; a lazily loaded errors module would recover most of it if that ever matters.

## Goal & prompt critique

- The grill rulings file was precise; the miss was reading it once and coding from memory. A short "rulings checklist" at the top of `SPEC.md` (one line per mechanism) would make the spec self-checking.

## Lessons (confidence-tiered)

- **HIGH — Critical:** Measure against the merge-base with the same compiler before trusting a baseline delta — the committed baseline was taken with `effect-tsgo` 0.51.1, and a uniform +5.8k across every fixture first looked like drift until the merge-base worktree showed it was real.
- **HIGH — Critical:** After a member rename, grep the whole repo for the old spelling, including JSDoc and object keys; the type checker only finds reads.
- **MEDIUM — Best practice:** When a gate flags rehashed clones, dedupe them if it is a few lines; it was cheaper than a suppression with an owner and an exit.
- **LOW — Consideration:** Keep typeperf fixture pairs (untouched / touched) for any laziness claim; the pair here confirmed `toTaggedUnion` costs 3,127 only when its type is read.
