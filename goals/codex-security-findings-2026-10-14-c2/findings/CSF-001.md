# CSF-001: C2 report constructor validates the placeholder digest too early

- Severity: Informational
- Codex ID: `commit:f903af80f27c819196b1f0ae0b0e8fdc`
- Source commit: `c9ca52c87e1bdeb8ed8e32c64e01dd41d107cab6`
- Owner: `@beep/semantica` C2 canary report assembly
- Status: confirmed functional regression; repair in progress

## Public Summary

The C2 canary built an opaque, digest-checked report while `reportDigest` still
held a zero placeholder. The constructor rejects that value before the workflow
can calculate the real digest. The Security Cloud analysis found no supported
attacker-controlled path or security boundary violation; the observed defect is
local canary reliability.

## Current-HEAD Validation

Verdict: confirmed at source commit `c9ca52c` and the current base. The live
`CanaryC2Live` path called `C2EvalReport.make` on the placeholder, while
`C2EvalReportDigestCheck` requires the report's actual canonical digest. The
source commit is an ancestor of this branch. Disposition: remediate the real
functional defect, then close the exact finding as Fixed after merge. No
security exploit is claimed.

## Remediation

Keep the provisional fields as a plain object, hash them with the unrefined
field schema, then invoke the checked `C2EvalReport.makeEffect` only with the
final digest. This follows the existing C1 report assembly pattern and retains
the final report's digest validation.
