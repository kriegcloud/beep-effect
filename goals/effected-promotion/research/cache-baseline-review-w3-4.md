# Cache baseline review: wave 3-4

Reviewed 2026-10-23 for wave 3-4 of `goals/effected-promotion` (`@beep/package-json`, plan decision W3-f).

`bun run beep quality cache-policy` reported 8 blocking findings, all
introduced by this branch and all of one kind: unreviewed expansion for the
new workspace `@beep/package-json`, on eight task tuples (`#build`, `#check`,
`#docgen`, `#lint`, `#lint:deprecated-apis`, `#lint:jsdoc`, `#lint:laws`,
`#test`).

`@beep/package-json` was scaffolded by `bun run beep create-package` in
foundation/modeling. Its scripts block is the generated task set
(`bun run beep lint package-scripts` reports 0 drifting manifests). It carries
no `turbo.json`, as the library scaffold emits none. Its runtime dependencies
are `effect`, `@beep/identity`, `@beep/jsonc`, `@beep/npm-spec`, `@beep/semver`
and `@beep/spdx`, all already in the graph, and it adds no third-party runtime
dependency. Its devDependencies are the test kit (`@beep/fc-runs`,
`@beep/memfs`, `@effect/vitest`, `@types/node`, `bun-types`) plus the
`validate-npm-package-name` differential oracle and its types.

The root manifest (`//`) changed too, without a reported drift: its catalog
gains two exact pins, `validate-npm-package-name` `7.0.2` and
`@types/validate-npm-package-name` `4.0.2`. Both were already in `bun.lock` at
those versions as transitives (of `npm-package-arg` and `shadcn`), so nothing
new installs. The `bun.lock` edit, regenerated by a plain `bun install` after
merging main, adds only the catalog entries and the new workspace. `bun run beep quality catalog-usage`
reports zero findings, and `bun run beep lint policy-fingerprint --check`
reports the fingerprint current: no fingerprinted adopter closure changed,
because this sub-wave adopts nothing in repo-cli, docgen or repo-utils. The
root `tsconfig.json`, `tsconfig.packages.json` and
`vitest.aliases.generated.json` edits only add the `@beep/package-json`
wiring.

Turbo coupling: no existing workspace gains `@beep/package-json` as a
dependency in this sub-wave, so no existing task's `^build` closure grows. The
closure growth for repo-utils, repo-cli and docgen is measured in 3-A3 and
3-A4, where those edges are added.

Two other inputs changed without a reported drift, and are not subjects:

- `@beep/identity`'s `src/packages.ts` gains the `$PackageJsonId` composer
  that `create-package` registers. This is a source edit; the manifest and
  task configuration are unchanged.
- `@beep/scratchpad`'s manifest gains `@beep/package-json`, because its lab
  importers (sbom `SbomMetadataSource` as a type-only import, workspaces
  `WorkspacePackage` and `PackageManagerName`) now import it. The policy does
  not report it, and its recorded projection is unchanged, as in waves 2b-1
  and 2d-1.

Recording these subjects accepts the existing posture for the new workspace
and the root catalog entries. No qualification is granted, and no other
subject changes.
