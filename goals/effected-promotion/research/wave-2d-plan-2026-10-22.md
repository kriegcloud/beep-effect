### Blocker that applies to all three plans: converting the nodes to S.Opaque makes the parser slower with every level of nesting

Measured on effect 4.0.5 under bun:

- **How `make` behaves.**
  - `S.Struct(...).make` re-walks and copies every descendant each time it is called.
  - `S.Class.make` accepts child instances as they are. This is the "union passes by identity" contract recorded in KNOWLEDGE.md:415-423.
  - `{ disableChecks: true }` does not help. It only skips refinements, and the constructor compiler still walks the whole tree (`SchemaParser.js:47`, `interpreter.js:89,112`).
- **Linear nesting, built bottom-up with a `make` at every node:**

  | depth | Opaque struct | Opaque, disableChecks | S.Class |
  |---|---|---|---|
  | 50 | 0.53 ms | 0.31 ms | 0.15 ms |
  | 100 | 1.13 ms | 0.81 ms | 0.09 ms |
  | 200 | 3.61 ms | 3.62 ms | 0.15 ms |
  | 400 | 16.2 ms | 16.3 ms | 0.16 ms |

  Doubling the depth roughly quadruples the Opaque time, while S.Class stays flat. `MAX_NESTING_DEPTH` is 256 (internal/limits.ts:24), so the cmark pathological suite will hit this.
- **Calling `make` at every node versus building plain data and calling `make` once at the root:**
  - Wide document (5,000 paragraphs × 5 texts): 7.2 ms versus 2.3 ms.
  - Depth 256: 4.0 ms versus 0.04 ms.

**Correction (binding before step 3 of 2d-1):** materialization builds plain typed values, and the one checked admission is a single `Root.make` (or a decode) at `Markdown.parse`. That pass is linear, and the KNOWLEDGE "checked admission boundary" stays one boundary. Supporting rules:

- Add an internal `trustedNode` constructor in `internal/nodes.ts` and keep it out of the public surface.
- This needs the node brand to allow plain construction internally. Either use the `{}` brand that `Md.model` already uses (`S.Opaque<InlineMath, {}>`), or one internal cast helper. Record whichever is chosen.
- If the schema-first detector rejects every option, keep the nodes as S.Class with a D-row. The reason is performance-contractual (construction by identity), not stylistic. Do not take this fallback silently.

The bridge has the same problem. `Md.model` nodes are already S.Opaque, so `Md.syntax` must build an encoded/plain `Document` and call `Document.make` once. It must not call `make` per node.

##### Hot loop rules

The rule flags only calls of the 32 String methods. Indexed reads, `.length`, and `RegExp` exec/test with lastIndex are free.

1. **Inline scanner.** `peek()` becomes `subject[pos] ?? ""`, and the trigger table is re-keyed by character with direct property lookup. Do not use `R.get` or `HashMap.get` there: each allocates an Option per character.
2. **Option-returning APIs.** Never call `Str.charCodeAt`, `codePointAt`, `charAt` or `indexOf` per character; they allocate Options, which caused the recorded 5x ACP-scanner slowdown.
3. **charAt.** Replace `charAt(i)` with `s[i] ?? ""`. Always keep the `?? ""` guard: `re.test(undefined)` tests the string "undefined".
4. **Positional tests.** `Str.startsWith`, `includes` and `endsWith` accept a position in v4.0.5. Hoist position-free predicates to module constants.
5. **Positional search.** Replace `indexOf(x, pos)` with `Str.includes(x, pos)` when only existence matters, otherwise with a cached global or sticky regex.
6. **slice.** Use `Str.slice`. In the stringify inner loop, prefer offset pairs.
7. **replace.** Callback replacers go through `@beep/utils/Str` `replaceWith`/`replaceAllWith`.
8. **Unicode classes.** Use sticky `\p{P}`/`\p{S}`/`\p{Zs}` regexes at a position instead of `codePointAt`.
9. **Cold paths.** MarkdownFormat, frontmatter, diagnostics and Mdast use the Option APIs freely.

#### 3. Source map (Md path to kit Position), and how it stays cheap

```ts
export const MdSourceOrigin = LiteralKit(["parsed", "recognized", "merged", "synthesized"])
export class MdSourceEntry extends S.Opaque<…>()(S.Struct({ position: Position, descendants: NonNegativeInt, origin: MdSourceOrigin })) {}
export class MdSourceMap extends S.Opaque<…>()(S.Struct({ entries: S.Array(MdSourceEntry) })) {
  static readonly empty: MdSourceMap
  static readonly positionAt: { (document: Document, path: DocumentSafetyPathSegment[]): (map) => Option<Position>; (map, document, path): Option<Position> }
}
```
- **Keyed by pre-order ordinal, not by path.** Document = 0. Every Md child field is named `children`, so a path is `["children", i, "children", j, …]`. `positionAt` walks it by skipping `descendants + 1` per earlier sibling: O(depth × siblings), no allocation, no path strings.
- **Shares kit `Position` instances.** For `parsed` nodes, entry cost is one small object per Md node. New Positions are built only for `recognized` (fused or sub-spans), `merged` and `synthesized` (zero-width at the parent's end, e.g. padded table cells) nodes.
- **Field segments are ignored.** A trailing non-node segment (`"href"`, `"value"`) resolves to the node's span, so `DocumentSafetyViolation.path` plugs straight in. `locateViolations` gives `MdLocatedViolation[]`, which is the map's `documentSafetyIssuesWithSource` graft.
- Offsets are kit UTF-16 code units, and Positions already carry line and column. Byte offsets are not stored. `sourceMap: false` returns `MdSourceMap.empty` for bulk callers. The map is transient and never persisted.

#### 6. No `Context.Service`

The bridge is a pure, total, synchronous function of `(MarkdownDocument, options-as-data)`. There is no environment, no resource or lifecycle, no alternative implementation to swap for tests, and no IO: codecs are fixed pure modules. A service would force `R` onto every caller and kill the sync `Result` path that #287-style callers need. Recognizer pluggability is the one variation point, and it is data (booleans now).
