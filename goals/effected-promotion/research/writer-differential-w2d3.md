# Writer differential: wave 2d-3

Measured 2026-10-23 for wave 2d-3 of `goals/effected-promotion` (SPEC D-52),
from the 2d-2 bridge-corpus ledger
(`packages/foundation/modeling/md/data/conformance/bridge-corpus.json`, D-51).

## Method

The ledger's writer column compares `Markdown.stringify` (the kit) with
`Md.render` for each of the 731 corpus examples: both texts are re-parsed
with `Md.parse` in the example's dialect, and a row is `divergent` when the
two re-parsed documents differ. On the 2d-2 ledger, 141 rows were divergent.
In every one of them the kit's text re-parsed to the bridged document and
`Md.render`'s text did not, so each divergence is a property of `Md.render`
or of what the bridge can express, never of the kit.

Each divergent row was then tagged by the feature of its bridged document
that explains the difference: an `&` before a character-reference shape, a
list whose items hold paragraphs, and so on (one predicate per cause, run
over the encoded document). A row can carry more than one tag. A row
resolved by this wave is attributed to the first writer cause it carries;
a row that stays divergent is attributed to its first cause outside the
writer. After the fixes, every row that stays divergent carries at least
one cause outside the writer.

The ledger is regenerated by `test/Md.bridge-corpus.test.ts`, so the counts
below are reproducible from the committed fixture. The per-row tagging was a
one-off measurement over the same inputs and is not committed.

## What remains, and who owns it

- Destination percent-encoding (19): the URL policy writes a canonical,
  percent-encoded destination (`/föö` as `/f%C3%B6%C3%B6`). The rendered
  link points at the same resource, so this is an intended normalization,
  not a writer bug.
- Decoded newlines (37) and unmerged Text runs (22): HTML escaped as text
  keeps its source newlines and lands as separate Text nodes. Markdown has
  no way to write a newline inside text that a `softBreak: "space"` parse
  keeps, and the reparse merges adjacent text. Both are bridge follow-ups
  (merge escaped-HTML text into its run; fold its newlines like soft
  breaks), outside the writer.
- Mixed list (1): Md marks looseness per item, Markdown per list, so a list
  with one tight and one loose item cannot be written.
- Kit gaps found on the way, owned by `@beep/markdown`: GFM email autolinks
  are recognized on decoded text, so `a\@b\.co` still links; a literal
  `http://x\.y` autolink keeps the backslash in its href.

## Review round 1 (PR #2141)

Three round-trip bugs the review found are fixed. Each one was pinned by a test in
`test/Md.render-escaping.test.ts` that failed before its fix.

- Intraword emphasis: an emphasis that opens or closes on emphasis took
  `_` delimiters even next to a letter or digit, where `_` cannot flank
  (`foo` + strong[em `bar`, `baz`] + `qux`). It now falls back to `*`
  when a neighbour touches a word character, and the fallback reads back
  (`foo***bar*baz**qux`). Emphasis directly inside emphasis within a word
  still has no Markdown spelling (`foo**bar**qux` reads as strong).
- Adjacent lists inside a list item: marker alternation ran only for
  sibling blocks at document, blockquote, admonition and footnote level,
  not for the blocks of a list item. A list item's block runs now
  alternate too. The blockquote, admonition and footnote-definition paths
  were already covered and are now pinned by tests.
- Inline math holding `\$`: the writer escaped an already escaped dollar,
  so each round trip added a backslash. It now escapes only a `$` behind
  an even run of backslashes, so `render(parse(render(x)))` equals
  `render(x)`. The round-trip property now generates math values holding
  `\$`, `\\$`, a backslash escape (`\_`) and bare `$` at either edge, and
  canonicalizes a bare `$` to `\$`. `mathValueSyntax` stays, narrowed to
  math values that hold Markdown inline syntax, edge whitespace or a
  trailing lone backslash, which the kit parses before the recognizer runs.

The writer differential is unchanged by these fixes (1 / 651 / 79, no row
newly divergent), since no corpus example holds these constructs. The
ledger's only change is the narrowed `mathValueSyntax` description.

## S44 bridge follow-up (#2137)

Escaped inline HTML now merges with surrounding Text runs while retaining its
newlines. Each merged run has one source-map entry spanning its contributing
nodes; inline math on either side remains recognized. The corpus generator
resolves exactly the 22 rows attributed to adjacent Text runs, with no newly
divergent rows. The writer totals are now 1 byte-equal, 673 reparse-equal and
57 divergent (previously 1 / 651 / 79).

The remaining 57 rows comprise 37 escaped-HTML newline rows, the unchanged
19 intended URL-policy rows and the unchanged mixed-list model row. Preserving
HTML newlines through Markdown writing and re-parsing remains open: the default
`softBreak: "space"` folds the writer's literal newlines. The escaped-email,
literal URL backslash and inline-math-before-digit gaps also remain open in
#2137. This follow-up closes only the adjacent-run part of that issue.
