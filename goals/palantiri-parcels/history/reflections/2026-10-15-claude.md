# Reflection — palantiri-parcels (2026-10-15, claude)

## Tooling experience

- **Worked:** one effect-first subagent per phase with an explicit gate list; pre-merging the next PR's head into the stacked lane so conflicts were resolved before each merge; the reviewed cache-baseline request flow once its "one request covers all changed subjects" rule was known.
- **Didn't:** the shared generated files (catalogs, baseline, tsconfig, identity registry, vitest aliases) conflicted on every main merge until #1825 sharded the catalogs; the reviewer bot only picks up the newest push, so an older head waited hours.
- **Frustrating:** gates that only run in pre-commit or hosted CI (docs oxlint, test-tsgo) surfacing after an agent reported every gate green.
- **Wished existed:** a single "lane gate" command that runs exactly what pre-commit plus the cheap gates plus test-tsgo will run.
